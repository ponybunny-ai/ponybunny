# KB-0012 | TUI 的 Dashboard 界面没有自动刷新

## 现象
1. 在输入框中输入内容并回车后，输入内容没有出现在上方消息区域。
2. 系统返回回复后，消息区域也没有自动刷新显示。
3. 消息区域滚动体验异常（看起来不随新消息更新，滚动不可用或无效）。
4. 消息框高度未适应内容长度，长文本被单行截断并显示省略号。

## 根因分析
- Dashboard 消息区渲染基于 `getConversationHistory(...)` 拉取结果，但刷新触发依赖不足：
  - 仅在会话切换或 `turnCount` 变更时拉取，未稳定跟随当前会话的 `conversation.new / conversation.response` 事件。
- `conversation.response` 到达后，应用层未及时刷新 session 列表，导致 `turnCount` 可能不更新，进一步阻断 Dashboard 的历史重拉。
- 消息内容渲染使用了单行截断逻辑（`truncateDisplayWidth(...)`），导致长消息固定为一行并显示省略号。

## 修复方案

### 1) 会话事件驱动的历史刷新（Dashboard）
- 文件：`src/cli/tui/components/views/dashboard-view.tsx`
- 改动：
  - 增加对当前会话相关 `conversation.new / conversation.response` 事件的监听（从 `state.events` 中提取最新事件 id）。
  - 将该事件标识纳入历史拉取 `useEffect` 依赖，事件到达时自动重新调用 `getConversationHistory(...)`。
- 结果：用户发送消息和系统回复后，Dashboard 消息区可自动刷新。

### 2) conversation.response 后刷新 session 列表
- 文件：`src/cli/tui/app.tsx`
- 改动：
  - 在 `conversation.response` 分支补充 `listConversationSessions({ limit: 20, lifecycleState: 'active' })`。
  - 将结果回写到 `app.setSessions(...)`，保证 `turnCount/lastMessage` 等摘要及时更新。
- 结果：确保会话摘要和 turn 计数与最新对话状态同步，避免 Dashboard 因元数据滞后不刷新。

### 3) 消息改为多行渲染，移除单行截断
- 文件：`src/cli/tui/components/views/dashboard-view.tsx`
- 改动：
  - 消息内容从单行截断改为 `<Text wrap="wrap">{turn.content}</Text>`。
  - 不再把内容强制压缩为单行，保留多行可读性。
- 结果：长文本不再“单行 + 省略号”，消息框可以按内容自然换行展示。
