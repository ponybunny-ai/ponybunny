# TUI 里选择 model 的功能缺失（主 TUI）

## 现状
1. 当前主 `pb` TUI（`src/cli/tui/`）里 `/models` 与 `/model` 命令均未实现；命令注册表里没有对应入口。
2. 当前主 `pb` TUI 里 `ctrl-m` 快捷键未实现。现有与此相关的快捷键是：
   - `ctrl-p`：命令面板
   - `ctrl-v`：视图切换
   - `ctrl-t`：在支持时切换 reasoning variants
   - `tab`：轮换 agent
3. 顶部状态栏当前不展示 model 信息。
4. 底部 footer 会显示一个 model label（来自 scheduler capabilities 的 models 列表首项），但这不是“用户手动选择的 model”。
5. scheduler capabilities 返回的 models 列表来源于 `llm-config`，不是“enabled + probe 成功”的过滤结果。
6. 相关但不同的现有能力：
   - CLI 已支持 `pb models list|probe|test`。
   - Chat UI（`src/cli/ui/chat-ui.tsx`）有 `/model` 选择器，但这不是主 `pb` TUI 的能力。

## 复现步骤
1. 启动主 TUI：`pb`。
2. 在输入框尝试输入 `/models` 并执行，观察无对应命令（未实现）。
3. 在主 TUI 中按 `ctrl-m`，观察无对应行为（未定义快捷键）。
4. 对比验证：按 `ctrl-p` 可以打开命令面板。

> 说明：上述可通过代码直接验证（见“参考/证据”），即使在 CI 中不启动交互式 TUI 也能确认结论。

## 期望结果
1. 提供 `/models` 命令或 `ctrl-m` 快捷键，打开 model 选择对话框：
   - 第一行是搜索框。
   - 下方是 model 列表，按 provider 分组。
   - 支持上下键选择、回车确认、ESC 取消。
2. 在输入框下方状态区域展示“当前用户选择的 model”（与 variants 显示区分开）。
3. 用户选择的 model 在执行任务时覆盖当前 agent 默认 model（需后端接口与执行器模型选择逻辑配合）。
4. 在 task/goal/run 相关数据中记录实际使用的 model（需求项）。

可用 model 的定义（需求）：provider 为 enabled 且 probe 成功；需结合 `pb models probe` 的健康状态数据与主 TUI 同步机制。
