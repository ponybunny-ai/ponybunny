# TUI 与模型配置链路存在多项缺陷

## 现状
当前主 TUI 与模型配置/展示链路存在以下问题：

1. 右下角 tab 区域缺少 `Sessions` 切换入口。
2. `Workstreams` 与 `Goals` 视图语义重叠（若同源数据仅展示粒度不同，应收敛为一个信息更完整的主视图），且默认未按当前 active session 过滤。
3. `Dashboard` 中间内容区域超出高度后，缺少稳定的鼠标滚动浏览行为。
4. TUI 上下区域显示的 model 不一致：上方显示 `M auth`，下方显示 `anthropic.claude-haiku-4-5-20251001`；但 `llm-config` 中 anthropic 未启用，属于后端到前端的贯通问题。
5. `/models` 下拉列出的是 `llm-config` 全量模型，而不是“provider.enabled=true 且 probe 后 `health.available=true`”的可用模型集。
6. `pb init` 仍错误复制 schema 到用户目录；schema 文件不应复制，且需要回归测试防止回归。
7. 用户通过 `/models` 选择 model 后，未回写到对应 agent 的 `agent.json`（例如 `lead`），导致下次启动无法自动加载并影响 agent 实际选模。

## 复现步骤
1. 启动主 TUI：`pb`。
2. 检查右下角 tab，确认是否存在 `Sessions`。
3. 切换到 `Goals` / `Workstreams`，观察默认列表是否仅展示当前 active session 相关数据。
4. 在 `Dashboard` 让中部内容超过可视区域，尝试鼠标滚轮上下滚动。
5. 查看顶部与底部 model 展示，记录是否一致，并对照 `~/.config/ponybunny/llm-config.json` 的 provider 启用状态。
6. 执行 `/models` 打开选择器，核对列表是否仅包含 enabled + healthy 模型。
7. 执行 `pb init`（可用 `--dry-run` + 临时目录），检查用户目录是否出现 schema 文件副本。
8. 在当前 agent（如 `lead`）下通过 `/models` 选择 model，重启后验证对应 `agents/lead/agent.json` 是否已持久化该值并生效。

## 期望结果
1. tab 区域提供 `Sessions` 入口，且切换行为稳定。
2. `Goals/Workstreams` 语义清晰且不重复；默认按当前 active session 过滤。
3. `Dashboard` 中部超长内容支持鼠标滚动浏览。
4. TUI 各区域 model 显示一致，且仅反映实际可用/生效模型。
5. `/models` 仅展示 enabled 且 probe healthy 的模型。
6. `pb init` 不复制 schema 到用户目录，并有回归测试保障。
7. `/models` 选模后可回写到对应 agent 配置并在后续会话自动生效。

## 验收标准
- [ ] 主 TUI 右下角 tab 显示 `Sessions` 且可正常切换。
- [ ] 进入目标视图后默认带有当前 session 过滤条件，列表不混入其他 session 数据。
- [ ] `Dashboard` 中部区域可通过鼠标滚轮稳定滚动（向上/向下均可）。
- [ ] 顶部/底部 model 展示一致，且与实际启用 provider 与运行时选模一致。
- [ ] `/models` 列表严格基于 enabled + `health.available=true` 过滤。
- [ ] `pb init` 不再复制 schema 文件到用户目录。
- [ ] 新增/保留回归测试覆盖 `pb init` schema 复制禁用场景。
- [ ] `/models` 选模后会写回对应 agent `agent.json`，重启后自动加载。
