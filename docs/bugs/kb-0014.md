# KB-0014 | TUI 指定模型未被 Scheduler 正确消费，执行链路回退到错误默认模型

## 1. 缺陷概述

- **缺陷编号**：KB-0014
- **发现阶段**：联调/端到端验证
- **当前状态**：✅ 已修复（代码、测试、构建均已验证）
- **严重级别**：High（影响主执行链路可用性）
- **优先级**：P0

## 2. 背景与问题陈述

用户在 TUI 中通过 `/models` 选择了指定模型（含 provider 前缀），且配置已落盘；但后续自然输入触发任务执行时，Scheduler 未使用该模型，而是进入错误的默认选模路径，最终命中已禁用 provider 或不可用 endpoint，导致执行失败。

问题的关键不是单个模型“不可用”，而是**用户指定模型未穿透 Session-First -> Goal/WorkItem -> Scheduler -> ProviderManager 的全链路优先级**。

## 3. 影响评估

### 3.1 业务影响

- 用户在 TUI 中设置模型后，行为与预期不一致，破坏可控性。
- 任务执行可能直接失败（例如默认模型绑定的 provider 被禁用）。
- 降低 Session-First 交互可信度，影响生产可用性。

### 3.2 技术影响

- 模型优先级策略在不同层行为不一致。
- 配置入口分裂（`model_hint`、workload 覆盖、tier）增加排障成本。
- 启动日志与实际配置口径存在偏差，误导运维判断。

## 4. 复现步骤

1. 在 `llm-config.json` 中仅启用单一 provider（例如 `CPA`），禁用 `openai/anthropic`。
2. 启动 gateway + scheduler。
3. 在 TUI 执行 `/models` 并选择某个明确模型。
4. 输入可执行请求（触发 session-first 创建目标并调度执行）。
5. 观察执行日志与 run 上下文：出现错误默认模型（如 `anthropic.claude-haiku-4-5-20251001`）并因 provider 不可用失败。

## 5. 期望结果

- 用户指定模型应立即生效，并在整个执行链路中保持最高优先级。
- 当用户设置为 `AUTO` 时，系统应回退到下一优先级（agent/tier）。
- TUI 切换 agent（tab）后，模型配置应按当前 agent 生效，而不是仅作用于默认 agent。

## 6. 根因分析（RCA）

### 根因 1：Session-First 物化阶段未注入用户模型

`SchedulerTaskBridge.createGoalFromConversation` 早期只写入了会话上下文，未把模型偏好注入 `goal.context.selected_model` 与 `workItem.context.model`，导致 Scheduler 执行阶段无法优先拿到用户模型。

### 根因 2：模型入口语义分散，优先级实现不统一

- workload 级历史键（`llm_model`/`primary`/`fallback`）与 tier/agent 规则并存，造成“看似可配、实际不一致”。
- 运行时模型覆盖未统一落到单一全局来源。

### 根因 3：日志口径与启用逻辑来源不一致

Scheduler 启动横幅曾基于“可用凭据/endpoint”视角输出 provider，可能显示 `openai, CPA`，即便配置里只启用 `CPA`，造成误判。

## 7. 修复目标

1. 打通 TUI 指定模型到 Scheduler 执行的全链路透传。
2. 收敛模型优先级：用户显式覆盖 > agent 配置 > tier。
3. 将运行时最高优先级覆盖统一写入 `ponybunny.json`，支持 `AUTO` 回退。
4. 修正启动日志口径，按“配置启用 provider”展示。

## 8. 修复方案与实施记录

### 8.1 会话链路修复（Session-First 注入模型）

- 在 `src/scheduler-daemon/session-intake.ts` 注入模型解析：
  - 优先读取 runtime `agent.modelOverrides.<agentId>`
  - 注入 `goal.context.selected_model`
  - 注入 `workItem.context.model`
- 增加测试：`test/scheduler-daemon/session-intake.test.ts`

### 8.2 模型覆盖统一到 `ponybunny.json`

- 新增 `agent.modelOverrides`（按 agent 维度）到 runtime 配置与 schema：
  - `src/infra/config/runtime-config.ts`
  - `docs/schemas/ponybunny.schema.json`
  - `docs/config-templates/ponybunny.example.json`
  - `src/infra/config/onboarding.ts`
- 支持 `AUTO`：表示禁用显式覆盖，降级到下一优先级。

### 8.3 RPC 与 TUI 收敛

- canonical 接口改为：
  - `system.agent.model_override.set`
  - `system.agent.model_override.get`
- 保留兼容别名：
  - `system.agent.model_hint.set/get`
- TUI 改为按当前选中 agent 设置/读取模型；模型选择器增加 `AUTO`。

### 8.4 ProviderManager 选模优先级收敛

- 统一链路：`runtime override > user model > agent model/model_hint > tier chain`
- 禁用 workload 级模型键参与选模：
  - `workloads.*.llm_model`
  - `workloads.*.primary`
  - `workloads.*.fallback`

### 8.5 启动日志口径修复

- Scheduler 启动横幅 provider 列表改为基于 provider-manager enabled endpoints（配置口径），不再误显示未启用 provider。
